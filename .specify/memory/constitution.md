# Physical AI & Humanoid Robotics – Essentials Constitution

## Core Principles

### I. Simplicity and Minimalism
All implementations must prioritize simplicity, minimalism, and clean design. Features should be concise, beginner-friendly, and avoid unnecessary complexity. The textbook must maintain a lightweight approach with minimal dependencies and fast build times.

### II. Technical Accuracy and Clarity
Content must be technically accurate, professionally written, and accessible to beginners while maintaining depth for intermediate learners. Explanations should be clear, concise, and free of jargon without proper explanation.

### III. Free-Tier and Lightweight Architecture
The textbook must be built using free-tier compatible technologies with no heavy runtime dependencies. All assets must be lightweight (SVG, small PNG) and the site must deploy successfully on GitHub Pages with fast load times.

### IV. Docusaurus-Based Delivery
The textbook must be built using Docusaurus as the static site generator and deployed on GitHub Pages. All content organization and navigation must follow Docusaurus conventions with clean, structured chapters.

### V. Structured and Organized Content
Content must follow the specified 6-chapter structure with logical progression and consistent formatting. Each chapter must meet relevance, accuracy, clarity, and conciseness requirements with proper headings and subheadings.

### VI. Research-Concurrent Writing Process
Content development must follow a research-concurrent writing approach where information is verified while writing. Focus should be on widely accepted robotics and AI fundamentals with concurrent validation of technical accuracy.

## Technical Requirements and Constraints

### Platform and Deployment
The textbook must be built using Docusaurus and deployed on GitHub Pages with successful local builds. The system must have no external runtime dependencies, use static-site only architecture, and maintain compatibility across mobile and desktop views.

### Content and Media Standards
All content must follow specified guidelines: clear and concise explanations, short paragraphs, bullet points for key ideas, diagrams in SVG when needed, minimal jargon with explained terminology, and consistent formatting across chapters. Only lightweight assets are permitted.

### Build and Validation Process
Each chapter must undergo validation for relevance to topic, technical accuracy, clear explanation, and concise length. The final product must pass terminology consistency checks and undergo a final proofreading pass before deployment.

## Development Workflow and Quality Assurance

### Content Generation and Refinement
Content must be generated and refined through Spec-Kit Plus and Claude Code workflows. Each phase (Research, Foundation, Analysis, Synthesis) must be completed with proper validation at each stage. The writing style must remain professional, technical but accessible, with minimal fluff and high-density, high-value content.

### Testing and Quality Checks
The system must pass all specified tests: npm start for local preview, npm run build for production test, sidebar and navigation validation, and mobile/desktop compatibility testing. All links must be functional and all assets must load properly.

### Success Criteria and Final Output
The final deliverable must meet all success criteria: clean Docusaurus-based textbook with exactly 6 complete chapters, simple readable UI, successful GitHub Pages deployment, no external runtime dependencies, free-tier friendly architecture, and fast load speeds.

## Governance

This constitution governs all aspects of the Physical AI & Humanoid Robotics – Essentials project. All development activities must comply with the stated principles and requirements. Amendments to this constitution require formal documentation and approval following the established Spec-Kit Plus procedures. All contributions must verify compliance with these principles, and any deviation must be explicitly justified and approved.
